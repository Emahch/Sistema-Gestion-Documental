Sistema de Gestión Documental
Objetivo General
Desarrollar un sistema de gestión documental que permita almacenar, organizar, consultar y compartir archivos digitales entre diferentes usuarios, aplicando una arquitectura cliente-servidor y una base de datos NoSQL orientada a documentos que permita administrar de forma flexible la información relacionada con archivos, carpetas, usuarios, permisos y actividades realizadas dentro del sistema.
Objetivos Específicos
Analizar los requerimientos del sistema e identificar las estructuras, relaciones y reglas necesarias para representar la información mediante un modelo de datos NoSQL.
Diseñar un modelo documental utilizando MongoDB, determinando adecuadamente la información que será almacenada de forma embebida y aquella que será representada mediante referencias.
Implementar una aplicación cliente y una aplicación servidor independientes, comunicadas mediante servicios web.
Aplicar operaciones de consulta y manipulación de información utilizando MongoDB.
Implementar reglas de negocio que mantengan la consistencia entre archivos, carpetas, permisos, almacenamiento y eliminación de recursos.
Desarrollar consultas y reportes que permitan analizar la información almacenada mediante distintos criterios de búsqueda, filtrado y agregación.
Descripción
Una organización dedicada a la prestación de servicios profesionales genera diariamente una cantidad considerable de documentos digitales relacionados con sus diferentes actividades. Entre estos se encuentran documentos administrativos, informes, contratos y otros recursos utilizados por sus empleados. (archivos en formato .txt y .md)
Actualmente, los documentos se encuentran distribuidos entre diferentes computadoras, carpetas locales y medios de almacenamiento. Esta forma de trabajo dificulta localizar información, controlar quién puede acceder a determinados archivos y mantener un registro de las operaciones realizadas sobre ellos.
Como parte de sus actividades, los empleados necesitan almacenar documentos, organizarlos mediante carpetas, consultarlos posteriormente y compartir determinados recursos con otros usuarios de la organización. Estas operaciones deberán realizarse de forma controlada, manteniendo información suficiente para determinar la propiedad, ubicación y acceso de cada recurso.
Debido al crecimiento constante de la cantidad y variedad de información almacenada, la organización ha decidido implementar un sistema informático que permita centralizar sus documentos y facilitar su administración. Para ello, lo ha contratado como desarrollador de software con la finalidad de analizar, diseñar e implementar una solución que responda a las necesidades planteadas.
Arquitectura del Sistema
El sistema deberá implementarse utilizando una arquitectura cliente-servidor. La solución estará compuesta por dos aplicaciones independientes: una aplicación cliente desarrollada con Angular 21 LTS y una aplicación servidor desarrollada con Node.js. La aplicación cliente consumirá los servicios proporcionados por el servidor mediante una API REST, mientras que el servidor será el único responsable de comunicarse con la base de datos MongoDB.

Roles del Sistema
La organización cuenta con diferentes usuarios que utilizarán la plataforma para almacenar y administrar documentos. Cada usuario deberá acceder mediante credenciales propias y tendrá acceso únicamente a las operaciones y recursos que le correspondan.
Administrador: Supervisa el funcionamiento general de la plataforma, administra usuarios y puede consultar información global relacionada con el uso del sistema.
Usuario: Administra sus propios archivos y carpetas, consulta los recursos a los cuales tenga acceso y puede compartir determinados elementos con otros usuarios.


Usuarios
El sistema deberá permitir administrar la información necesaria para identificar y autenticar a los usuarios de la organización.
Los usuarios podrán permanecer activos o inactivos. La desactivación de un usuario no deberá provocar la pérdida de la información histórica relacionada con sus documentos o actividades.
Carpetas
Los usuarios podrán organizar sus documentos mediante carpetas y subcarpetas. La estructura deberá permitir navegar entre los diferentes niveles, consultar el contenido de cada carpeta y modificar la organización de los recursos almacenados.
Las operaciones realizadas sobre una carpeta deberán considerar los elementos asociados a ella y evitar estructuras inconsistentes dentro de la jerarquía.
Archivos
Los usuarios podrán almacenar diferentes tipos de archivos digitales dentro de la plataforma (.txt y .md). Cada archivo deberá conservar suficiente información para determinar su propietario, ubicación, características principales y las fechas relevantes asociadas a su almacenamiento.
El sistema deberá permitir cargar, descargar, consultar, renombrar, mover y eliminar archivos. También deberá facilitar su localización mediante búsquedas, filtros y mecanismos de clasificación que el estudiante considere adecuados.
El contenido de los archivos deberá almacenarse utilizando mecanismos proporcionados por MongoDB para este propósito y deberá poder recuperarse posteriormente sin pérdida de información.


Compartición y Permisos
Los usuarios podrán compartir determinados archivos y carpetas con otros usuarios registrados dentro de la plataforma. El propietario deberá establecer el nivel de acceso otorgado sobre cada recurso compartido. (lectura, edición y comentar)
Como mínimo, el sistema deberá diferenciar entre permisos de lectura y edición. El propietario podrá modificar o retirar posteriormente los permisos concedidos, y el sistema deberá garantizar que un usuario no pueda acceder o modificar un recurso para el cual no posea autorización.
Papelera
La eliminación normal de un archivo o carpeta no deberá provocar inmediatamente su eliminación definitiva. Los recursos eliminados deberán trasladarse a una papelera desde la cual el propietario pueda consultarlos, restaurarlos o eliminarlos de forma permanente.
Las operaciones de restauración y eliminación definitiva deberán mantener la consistencia de la organización de carpetas y del espacio de almacenamiento utilizado por el usuario.
Historial de Actividad
El sistema deberá mantener información relacionada con las principales operaciones realizadas por los usuarios. El historial deberá permitir determinar qué usuario realizó una acción, sobre qué recurso fue realizada y cuándo ocurrió.
La información registrada deberá permitir consultar posteriormente la actividad relacionada con archivos, carpetas y recursos compartidos.
Reglas Generales del Sistema
Los usuarios únicamente podrán acceder a los recursos propios o a aquellos para los cuales posean los permisos correspondientes.
La estructura jerárquica de carpetas deberá mantenerse consistente y no deberá permitir ciclos o referencias inválidas.
El movimiento de archivos y carpetas deberá mantener correctamente su ubicación dentro de la estructura correspondiente.
Los recursos enviados a la papelera no deberán mostrarse dentro de las consultas normales de archivos y carpetas.
La restauración y eliminación definitiva deberán conservar la consistencia de la información relacionada con los recursos afectados.
La información histórica necesaria para la auditoría y generación de reportes deberá conservarse.
El estudiante deberá poder justificar las decisiones tomadas para representar la información mediante documentos embebidos o referencias.
Información Inicial
El sistema deberá contar con información suficiente para demostrar su funcionamiento y permitir la generación de los reportes solicitados. Como mínimo, la carga inicial deberá incluir:
3 usuarios.
Una estructura de carpetas y subcarpetas distribuida entre los diferentes usuarios.
50 archivos distribuidos entre diferentes usuarios, carpetas y tipos de archivo.
Al menos 20 operaciones de compartición entre usuarios.
Recursos enviados a la papelera.
Información suficiente en el historial de actividad para demostrar las principales operaciones implementadas.
Módulo de Reportes
El sistema deberá permitir consultar y presentar información relevante mediante filtros y criterios de búsqueda. Las consultas que requieran agrupación, acumulación o análisis deberán aprovechar las funcionalidades proporcionadas por MongoDB.
Reportes de archivos y almacenamiento
Cantidad de archivos agrupados por tipo.
Archivos almacenados dentro de un rango de fechas.
Archivos con mayor cantidad de operaciones registradas.
Reportes de usuarios
Top 10 usuarios con mayor cantidad de archivos almacenados.
Usuarios con mayor cantidad de recursos compartidos.
Reportes de compartición
Archivos compartidos con mayor cantidad de usuarios.
Recursos compartidos por un usuario seleccionado.
Recursos recibidos por un usuario seleccionado.
Reportes de actividad
Historial de actividad de un usuario dentro de un rango de fechas.
Cantidad de operaciones agrupadas por tipo.
Cantidad de operaciones realizadas agrupadas por período.
Principales acciones realizadas dentro del sistema.

Importante
La aplicación cliente deberá desarrollarse utilizando Angular 21 LTS.
La aplicación servidor deberá desarrollarse utilizando Node.js (express o nextjs).
El gestor de base de datos será MongoDB.
El contenido de los archivos deberá almacenarse utilizando funcionalidades proporcionadas por MongoDB. No será válido almacenar únicamente la ruta hacia un archivo ubicado localmente en el servidor.
El estudiante será responsable de diseñar el modelo documental utilizado por la aplicación y deberá justificar las decisiones relacionadas con documentos embebidos, referencias e índices.
La base de datos deberá poder inicializarse con información suficiente para realizar la calificación del proyecto.
